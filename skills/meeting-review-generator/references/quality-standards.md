# Quality Standards

The **Final Quality Gate**: the checklist `SKILL.md` STEP 4.4 runs on the finished report, fixing every failed check before the file is written. Each check appears once. The rules behind the structure live in `output-structure.md`; the rules behind language and formatting live in `writing-guidelines.md`.

---

## Final Quality Gate

### Content completeness
- [ ] Every theme, decision, action, open point, and critical aspect from the transcript is captured
- [ ] Cross-check against the transcript: scan for decision keywords ("decided," "agreed," "approved"), action keywords ("will," "assigned to"), question keywords, and emphasis keywords ("critical," "urgent," "risk")
- [ ] All participants identified in the Introduction
- [ ] No fabricated details; uncertainties acknowledged; names, dates, and numbers faithful to the transcript

### Structure
- [ ] Four sections present and in order, titles in the report language: Introduction, Discussed Themes, Summary, Follow-up
- [ ] Detail per theme proportional to its STEP 2.2 relevance level
- [ ] Every theme subsection follows the same component order
- [ ] Summary consolidates only — no new information
- [ ] Every Follow-up action traces back to a theme
- [ ] All cross-references resolve to the right theme, with names spelled consistently

### Formatting
- [ ] Every decision, open point, action, critical aspect, and assignee name bolded with its label
- [ ] Bolding not overused — only the essential information
- [ ] Bullets for unordered items, numbers for ordered or prioritized items, parallel grammar within each list
- [ ] Descriptive, specific headers; consistent ## / ### / #### hierarchy
- [ ] Paragraphs 3-6 sentences, one main idea each, no walls of text
- [ ] Acronyms defined on first use; terminology consistent throughout

### Actionability
- [ ] Every action specific and measurable enough to start immediately
- [ ] One primary owner per action — a person or a named team, never a vague "the team"
- [ ] Deadlines or timeframes captured whenever the transcript gives them; urgency visible
- [ ] Dependencies and blockers stated where they exist
- [ ] Success criteria recorded when specified

### Language
- [ ] Correct language as selected (Italian default, English, or other)
- [ ] Correct labels for the language ("**Decisione**:" / "**Decision**:" and equivalents)
- [ ] Professional tone; active voice preferred

### Delivery
- [ ] Correct format as selected: DOCX, PDF, MD, or the user's other choice
- [ ] Filename `meeting-review-report-[YYYY-MM-DD]-[LANG].[ext]`, date from the transcript (today's date if absent; most recent meeting date for a consolidated report)
- [ ] File created and surfaced per STEP 4.5 (downloadable file on claude.ai, absolute path on Claude Code)

### Format-specific (apply the one that matches)
- [ ] **DOCX**: Word heading styles applied; consistent styling; sensible page breaks and margins
- [ ] **PDF**: professional font and clear hierarchy; print-ready appearance
- [ ] **MD**: valid syntax; renders correctly in preview
